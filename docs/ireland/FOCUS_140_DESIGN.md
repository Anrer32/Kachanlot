**Статус: поузловой дизайн отсутствует, игровое дерево не создано.**
Основание — запрос второго этапа от 17 ноября 2026 года, HoI4 1.19.4.1.
Согласованы количество направлений, диапазоны кодов и смысловые группы
взаимоисключений. Названия, конкретные связи, условия и координаты не предоставлены.
Пункт 1 запроса разрешает в такой ситуации подготовить документ для согласования,
не выдумывая отсутствующие фокусы. Именно этот вариант выполнен.

## 3. Утверждённые смысловые взаимоисключения

| Группа | Варианты | Что ещё требуется определить |
| --- | --- | --- |
| Политический курс | Fianna Fáil / Fine Gael / Labour / национальное единство / радикальные альтернативы | Код входного фокуса каждого варианта, доступность и условия перехода |
| Экономическая стратегия | Государственная индустриализация / экспорт | Коды развилки, общие узлы до/после неё |
| Аграрная политика | Модернизация / защита существующих хозяйств | Коды выбора и последствия для общих экономических узлов |
| Армия | Профессиональные войска / территориальная оборона | Коды и перечень совместимых общих военных узлов |
| Дипломатия | Нейтралитет / союз с Британией / континентальная дипломатия / коллективная безопасность | Коды, переходы при войне и исчезновении партнёра |
| Альтернативная история | Радикальная республика / корпоративизм / сближение с Содружеством / социалистическая революция / кельтская федерация | Коды входов и связь с политическими вариантами |

Группы обозначают максимум один выбранный вариант внутри группы. Нельзя
произвольно считать их всеми входными кодами подряд: это ещё не утверждено.
В частности, нужно явно решить, является ли «радикальные альтернативы» общим
политическим шлюзом для всей A-ветки или только части её путей. Автоматическая
блокировка Commonwealth-пути или национального единства этим шлюзом недопустима.

После выбора кодов сформировать симметричные попарные `mutually_exclusive`
для входов одной группы. Не делать взаимоисключающими все 28/30 узлов направления:
потомки выбранного пути должны оставаться доступны. Между разными группами
запреты вводятся только при явно описанном конфликте дизайна.

## 4. Как заполнить реестр, не придумывая содержание

Одна строка CSV — один зарезервированный слот. Сейчас у всех строк
`design_status = awaiting_design`, `effect_status = awaiting_design`.
Пустая ячейка означает **не определено**, а не «условий нет» или «это корень».
Ни одна строка пока не является утверждённым игровым фокусом.

| Поле | Требуемое содержание перед генерацией игрового файла |
| --- | --- |
| `code`, `planned_id`, `direction` | Стабильная связь с утверждённым диапазоном |
| `title_ru`, `title_en` | Утверждённые имена; историческое или альтернативное содержание пояснить в design note |
| `design_note` | Смысл, историческое основание либо явная маркировка альтернативы |
| `prerequisite_groups` | Явный список групп родителей с AND/OR-семантикой; корневому узлу явно указать `[]` |
| `mutually_exclusive` | Полный список ID конфликтующих входов; явно `[]`, если их нет |
| `available`, `bypass` | Проверенные условия country scope либо явное решение об отсутствии условий/блока |
| `relative_position_id`, `x`, `y` | Якорь и смещение; корни задаются отдельно, отсутствие якоря не выводится из пустой ячейки |
| `cost` | Утверждённая стоимость; не назначать всем произвольные 35/70 дней |
| `icon` | Проверенный спрайт из мода/vanilla, не выдуманное имя |
| `effect_spec`, `effect_status` | Описание будущего результата и стадия реализации, отдельно от графа |
| `design_status` | `awaiting_design` → `proposed` → `approved`, с записью утверждённой ревизии |

CSV одновременно является **отдельным реестром нереализованных эффектов**:
сейчас у всех 140 слотов содержание эффекта ещё не определено. После утверждения
содержания менять `effect_status` на `deferred`, затем на `implemented` только
в соответствующем контентном этапе. Не отмечать `implemented` за пустой reward.
Не создавать бонусы, флаги, события, идеи или scripted effects только для
заполнения пустой колонки. Будущий каркас может использовать пустой
`completion_reward` с явной пометкой в описании о неготовом результате; это
техническое решение надо подтвердить при согласовании каркаса.

## 5. Предлагаемые технические решения для согласования

- Пять отдельных горизонтальных зон P/E/M/D/A с собственными якорями и читаемыми
  промежутками; внутриветочные пути размещать от утверждённого графа, а не делать
  пять цепочек по 28 узлов ради счётчика. Точные размеры зон зависят от развилок.
- Отдельно проверить ацикличность `relative_position_id`: визуальные якоря
  образуют собственный граф и не обязаны совпадать с prerequisites.
- Новое дерево выбирается для IRE, не меняя чужие страны и generic-дерево.
  Вес выбора и поведение DLC сверить с текущим модом и vanilla 1.19.4.1.
- Наличие партийных ветвей не является основанием автоматически переключать
  правительство или выдумывать партийную популярность. Для каждого входа нужно
  выбрать условие: уже действующее правительство, историческая дата, ранее
  завершённый узел или реальное событие. Никаких ссылок на несуществующие флаги.
- Описание пустой награды должно быть честным: дерево остаётся техническим
  каркасом. Не создавать видимость законченного контента через общий бонус PP.
- После утверждения имен создать RU/EN пары ID и `_desc`, UTF-8 BOM, без сырых
  кодов P01 как окончательного названия. Временные иконки брать только из
  проверенных ресурсов; существующая ссылка в другом дереве ещё не доказывает
  наличие спрайта без нужного DLC.

## 6. План проверок будущего каркаса

1. Ровно 140 определений `focus`, точные диапазоны 28/28/28/26/30, уникальность
   ID и отсутствие дополнительных shared-фокусов в этом счётчике.
2. Все prerequisite/exclusion/relative-position ссылки разрешаются; отсутствуют
   ссылки на самого себя; исключения симметричны. Проверить scope и грамматику
   версии, не ограничиваясь подсчётом скобок.
3. Граф зависимостей и граф визуальных якорей проверены на циклы независимо.
   Для prerequisite-групп учтена реальная AND/OR-семантика HoI4.
4. Для каждого узла существует хотя бы один допустимый путь с учётом исключений
   и доступности. Завершение одного пути не должно требовать двух взаимоисключённых
   входов. Отдельно проверить общие узлы после альтернативных развилок.
5. Различать «недоступен в историческом сценарии по дизайну» и «недоступен во всех
   сценариях по ошибке». Для дат/внешних стран/идеологий нужна матрица сценариев,
   а не один топологический обход. Взаимоисключаемость не является циклом.
6. Нет пересечений координат, линии читаемы, пять направлений различимы; условные
   скрытия не ломают layout. Реальная проверка вида требует запуска игры.
7. RU/EN-ключи, GFX, filters, tree selection и доступность проверены в 1.19.4.1.
   Подтвердить выбор IRE-дерева в новой партии и отсутствие замены у других стран.
8. Каждая неготовая награда сопоставлена строке реестра. Сохранены шесть духов
   первого этапа и общие законы/нефтяная механика/host tool/ENG/GER-контент.

## 7. Фактический отчёт этой ревизии

- Проверено отсутствие поузлового дизайн-документа в текущих `docs/` и дерева IRE
  в `common/national_focus/`.
- Создано ровно 140 строк резервирования: 28 P, 28 E, 28 M, 26 D, 30 A;
  уникальность кодов и предлагаемых ID проверена, пропусков нет.
- Все 140 эффектов имеют статус `awaiting_design`; награды не выдуманы.
- Локальные Markdown-ссылки и `git diff --check` проверены.
- Игровые файлы, локализация и существующие инструкции не изменены.
- Проверки игрового графа/доступности/синтаксиса и запуск HoI4 **не выполнялись**:
  самого графа ещё нет. Нельзя сообщать «циклов нет» по пустым prerequisite-ячейкам.

## 8. Что требуется для продолжения

Предоставить существующий утверждённый дизайн с описаниями P01–A30 либо заполнить
и согласовать этот реестр: названия/смысл каждого узла, родители, коды входов
перечисленных взаимоисключений и условия политических путей. Стоимость, координаты,
иконки и политику пустых наград можно отдельно поручить разработчику как
технические решения после определения смыслового графа.

До этого резервирование 140 ID не следует называть деревом из 140 фокусов.
